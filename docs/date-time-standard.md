# 全项目日期与时间标准

唯一实现入口：`src/utils/calendarTime.ts`。服务端、浏览器和脚本读取的业务日期均按北京时间（UTC+8）划分，不跟随机器或浏览器时区。

## 统一规则

- 自然日为 `[当日 00:00:00+08:00, 次日 00:00:00+08:00)`；内部日期范围统一左闭右开。
- 带 `Z` 或显式偏移的时间戳先转换为 UTC+8，再归属日期；不能直接截取时间戳的前十个字符。
- 无时区的日期时间和 `datetime-local` 输入按 UTC+8 解释；日期值 `YYYY-MM-DD` 本身是业务自然日，不进行额外偏移。
- 所有日期范围选择器的起止日期都表示所选当日 00:00（UTC+8），统一为 `[开始日 00:00, 结束日 00:00)`。结束日期不加一天，不因模块不同而改变语义。质检、Workbench 数据统计、首页采集日期筛选及分享链接采用同一标准。
- “今天”显式设置为今天至明天，“近 7 天”显式设置为六天前至明天。结束日期选择次日是快捷选项的明确结果，不是对用户输入的隐式转换；首尾同日表示空范围，并在界面提示。
- 日期校验、跨日运算、周范围和时间显示均调用共享工具；非法日期不能自动滚动到下月，缺失日期不能补造为今天。
- 日期选择器、请求参数和筛选摘要使用相同的起止日，摘要明确显示双方当日 00:00 以及含/不含规则。仅设置起始日或结束日时，摘要明确另一侧不限。
- 原始记录的显式 UTC/带偏移时间戳可以继续存储，不改写历史文件；仅在解析、展示或分日时应用统一标准。没有时区证据的历史日期标签保留原本日期，不猜测其原始时区。

## 调用约定

- 解析时间戳：`parseCalendarTimestamp`；分日：`calendarDayKey` / `tryCalendarDayKey`。
- 日期校验：`isCalendarDay`；日界与日期运算：`calendarDayStart`、`calendarDayBounds`、`shiftCalendarDay`、`calendarDayDifference`、`calendarDays`；数据集采集日期跨度与筛选范围的交集统一使用 `calendarDaySpanOverlaps`。
- 筛选和预设：`calendarDateInputRange`、`calendarDayInRange`、`calendarDateRange`；展示：`calendarDateTime`、`formatCalendarDateTime`。
- `reviewTime.ts` 只保留旧调用名称，日期输入适配也调用共享工具，不另行实现时区、午夜或结束日规则。
- 采集时间与质检标记时间仍是不同业务字段；统一自然日标准不意味着可以互相替代时间来源。

## 回归约束

`calendarTime.test.ts` 验证 UTC+8 午夜两侧、偏移时间、无时区输入、跨月/跨年/闰日、日期预设和跨模块一致性，并在 UTC、上海、洛杉矶三个独立进程中对照结果。

`calendar-usage.test.ts` 扫描生产代码，阻止新增按宿主本地日期、UTC 截断或独立日期格式器实现自然日逻辑；共享工具以外的模块只能复用统一入口。

跨模块回归使用同一组记录，核对质检、Workbench 和首页筛选在完整范围、单侧开放范围、结束日零点及首尾同日时结果一致。累计覆盖率的 `asOfDay` 表示该日 00:00 的不含截止边界；每日明细的截止边界明确为次日 00:00。原始标记时间保留真实时分秒，不截断原始记录。
